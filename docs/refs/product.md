# 一、平台应该具备哪些功能？

## 1. 首先明确平台的目标用户

根据技术文档，目前的算法主要解决三个问题：

- 将 ECMWF、GFS 等多源气象数据融合，提升背景场预测质量。
- 利用地形信息，将约 10 km 的气象场降尺度至约 3 km。
- 通过残差扩散模型输出概率集合预报，同时控制大尺度背景的一致性。

系统能够处理气温、气压、风场和降水等气象要素。TECH_DOC

但这些只是算法能力，并不是用户最终想要的功能。

**真正的用户并不关心模型用了多少层 U-Net，而是关心模型能否帮助他们更准确、更快速地完成气象分析与业务决策。**

因此，我建议将目标用户划分为四类。

| 目标用户 | 核心需求 | 平台应该提供的价值 |
|---|---|---|
| **气象预报员、气象业务人员** | 查看高精度天气预报、分析局地天气变化 | 精细化气象地图、气象要素分析、预报对比、概率预报 |
| **气象科研人员、AI研究人员** | 验证降尺度效果、分析模型表现 | 模型实验、结果对比、精度评估、参数调整 |
| **行业应用人员** | 根据气象条件进行业务决策 | 风电气象分析、强降水风险辅助研判、低空气象分析 |
| **气象数据与系统工程师** | 获取模型产出的数据并集成到其他系统 | 数据管理、预测任务管理、气象数据导出、API服务 |

这里需要特别考虑一个问题：

**气象业务人员和气象科研人员对平台的需求存在明显差异。**

气象业务人员需要简单直观地查看气象产品；科研人员则希望深入分析算法效果与控制参数。

因此，平台应该同时具备业务应用能力和专业分析能力，但不必将所有专业参数暴露给普通用户。

## 2. 平台核心功能规划

我建议将平台划分为 **8 个核心功能模块**。

| 功能模块 | 主要功能 | 优先级 |
|---|---|---|
| ① 气象综合驾驶舱 | 气象数据概览、预测任务概况、重点区域气象概况 | P0 |
| ② 智能降尺度预测 | 数据选择、区域配置、模型推理、预测任务管理 | P0 |
| ③ 气象地图可视化 | 温度、气压、风速、降水等高分辨率气象场展示 | P0 |
| ④ 多源气象对比分析 | EC/GFS与降尺度结果对比、局部放大、差异分析 | P0 |
| ⑤ 概率集合预报分析 | 多集合成员展示、预测区间、不确定性分析 | P0 |
| ⑥ 精细化气象风险分析 | 极端降水、大风等风险指标及区域分析 | P1 |
| ⑦ 模型性能评估 | RMSE、MAE、CRPS、模型对比、参数敏感性分析 | P1 |
| ⑧ 气象产品与数据服务 | 结果导出、分析报告、数据下载、API接口 | P1 |

其中，P0代表第一版 Demo 应优先完成的核心能力，P1代表建议扩展的功能。

接下来具体分析。

### ① 气象综合驾驶舱（Dashboard）

**目标：让用户进入系统之后，快速了解当前有哪些气象数据、预测任务，以及可以开展哪些气象分析。**

这是平台首页，不建议将其设计成单纯的算法介绍页面。

建议展示以下内容：

| 功能 | 具体设计 |
|---|---|
| 气象数据概览 | 当前可用的ECMWF、GFS数据，最新数据时间 |
| 区域气象概览 | 显示当前研究区域的气温、降水、风速等信息 |
| 降尺度能力概览 | 展示10 km → 3 km的空间分辨率提升 |
| 预测任务概览 | 最近执行的降尺度任务及其运行状态 |
| 气象要素速览 | 气温、气压、风速、降水等关键指标 |
| 快捷操作 | 新建降尺度任务、查看气象地图、进入分析中心 |

**设计重点：**

首页应当以一张大型的交互式气象地图作为视觉中心。

地图可以直接展示已经生成的3 km气温场、风速场或者降水场。

用户点击地图上的某个位置后，可以查看该位置的具体预测值。

这样能在第一时间让用户理解产品的实际用途，而不是仅仅看到一些模型运行指标。

### ② 智能降尺度预测（Downscaling Studio）

这是整个平台最核心的业务功能。

它直接连接现有的 MRA-ResUNet、Topo-EDSR 和 CSC-ResDiff 三个模型。

建议将功能分为三个部分。

**第一部分：预测任务配置**

用户可以设置：

- 选择预测区域。
- 选择ECMWF、GFS气象数据。
- 选择预报起报时间与预报时效。
- 选择预测的气象要素。
- 选择确定性预报或概率集合预报。
- 选择集合成员数量。

这里需要注意：区域和时间只能在现有模型、数据及推理程序实际支持的范围内选择，不应在 Demo 中默认支持任意区域、任意日期的实时预测。

**第二部分：智能降尺度执行**

系统通过现有模型完成以下流程：

ECMWF + GFS → MRA-ResUNet → Topo-EDSR → CSC-ResDiff → 3 km预测结果。

前端不需要将复杂模型参数全部展示给普通用户。

可以将过程抽象为：

1. 多源气象数据融合
2. 地形感知精细重建
3. 随机气象细节生成
4. 跨尺度一致性控制

这四个阶段可以设计为可视化的任务执行流程。

**第三部分：预测结果管理**

每次降尺度任务完成后，生成一个独立结果记录。

用户可以查看：

- 任务名称与运行状态
- 预测时间与地理范围
- 输入数据来源
- 模型版本
- 输出空间分辨率
- 预测结果
- 下载入口

**建议：提供“快速预测”和“专业预测”两种入口。**

快速预测面向普通气象业务用户，只需要选择区域、时间和气象要素。

专业预测面向科研用户，可以进一步设置集合数量、采样参数和CSC控制参数。

这样既不会增加普通用户的操作门槛，又能突出项目的算法创新性。

### ③ 气象地图可视化（Weather Map Explorer）

**这是我认为整个平台最值得投入设计资源的功能。**

你的模型最终输出的是高分辨率空间气象场。

如果只将结果展示成几张静态图片，就浪费了数据本身的空间分析价值。

建议设计一个专业的交互式GIS气象地图。

用户可以自由切换以下气象图层：

| 图层 | 展示方式 |
|---|---|
| 2米气温 T2m | 温度色斑图、等温线 |
| 地面气压 SP | 气压色斑图、等压线 |
| 10米风速 | 风速热力图、风向箭头 |
| 10米风场 U10/V10 | 风矢量图 |
| 总降水 TP | 降水分布图 |
| 地形高程 DEM | 地形阴影、高程图层 |

其中，风速可以由U10和V10两个分量计算得到，无需额外训练一个模型。

**建议支持的交互操作：**

- 地图缩放与平移
- 气象图层切换
- 时间轴切换
- 地图点击查询
- 指定区域放大
- 气象变量图例控制
- 地形与气象图层叠加

例如，用户选择“10米风速”，地图就显示整个预测区域的风速分布。

当用户放大某个山区时，可以观察降尺度后更加细致的风场结构。

这可以非常直观地体现Topo-EDSR引入地形先验的技术价值。

在成熟气象业务系统中，交互地图与逐时次图层浏览也是重要的产品形式。例如，NOAA的nowCOAST提供多图层及时间动画，ECMWF的ecCharts支持交互式气象图表。[海图网](https://www.nauticalcharts.noaa.gov/learn/nowcoast.html?utm_source=chatgpt.com)

### ④ 多源气象对比分析（Forecast Comparison）

这一功能的核心目标是：

**让用户直接看到使用智能降尺度模型之前和之后，气象预报产生了哪些变化。**

建议提供三种对比方式。

**A. 原始预报与降尺度结果对比**

支持选择：

- ECMWF原始预报
- GFS原始预报
- 多源融合结果
- 3 km确定性预测结果
- 最终集合预测结果

可以采用左右双地图布局。

例如：

左侧显示ECMWF原始10 km风场，右侧显示模型重建后的3 km风场。

两张地图共享地理位置、缩放比例和颜色刻度。

用户就可以清晰观察地形相关的局地风场变化。

**B. 地图滑动对比**

提供一个左右滑动分割线。

拖动分割线即可在同一区域查看原始预测与降尺度结果。

这是非常适合Demo演示的功能。

**C. 预测结果差异分析**

展示不同结果之间的数值差异。

例如：

- 降尺度结果相对ECMWF的温度差异
- 多源融合前后的气压变化
- 不同预测结果之间的局地风速差异

需要强调的是，**结果出现更多细节，并不等于预测一定更准确**。

如果存在对应的高分辨率参考数据，还应支持与参考场进行对比，并显示误差指标；如果没有参考数据，则只能展示预测差异，而不能将其直接解释为精度提升。

### ⑤ 概率集合预报分析（Ensemble Forecast Analysis）

这是你们产品区别于普通AI超分辨率系统的一个关键功能。

大多数简单的超分辨率模型只输出一个确定性结果。

而当前产品能够通过残差扩散模型生成多个随机集合成员，从而表达预报不确定性。

因此，我建议将**概率集合预报分析作为平台的一项核心能力，而不是隐藏在模型高级设置里。**

具体包括：

**A. 集合成员浏览**

例如，某次任务生成10个集合成员。

平台支持：

- 查看不同集合成员
- 比较不同成员的空间分布
- 查看集合均值
- 查看集合标准差

**B. 预测不确定性地图**

通过集合离散度反映不同区域预测结果的不确定程度。

例如，某区域不同集合成员的降水量差异较大，就可以在地图上突出该区域的预测分歧。

需要注意，集合离散度代表预测成员之间的分散程度，只有经过验证和校准，才能进一步将其解释为可靠的概率不确定性。

**C. 气象要素概率分布**

用户点击某个地图位置，可以查看：

- 气温预测分布
- 风速预测分布
- 降水预测分布
- 预测分位数

可以使用直方图、箱线图或概率区间图展示。

ECMWF的集合预报产品也采用针对指定位置的集合气象图（Meteogram），展示不同气象变量随预报时效变化的概率分布。[ECMWF Confluence Wiki](https://confluence.ecmwf.int/spaces/FUG/pages/673551076/Section%2B8.1.4%2BMeteograms?utm_source=chatgpt.com)

**D. 极端天气阈值概率分析**

允许用户设置阈值。

例如：

某区域未来指定时段内，降水量超过某个阈值的集合成员占比是多少？

需要使用与TP数据一致的降水累计时段。

平台即可通过符合条件的集合成员比例，计算经验超阈值概率。

这一功能可以直接服务于下一模块的气象风险辅助研判。

### ⑥ 精细化气象风险分析（Weather Risk Intelligence）

前面五个模块主要面向气象分析。

这个模块则负责进一步将气象预测转化为业务参考信息。

我建议第一版先设计两个风险分析场景。

**场景一：强降水风险辅助研判**

面向城市应急、区域气象服务等用户。

可以支持：

- 指定时段累计降水分析
- 强降水阈值超越概率
- 高降水区域识别
- 降水空间分布与行政区叠加
- 潜在重点关注区域筛选

例如：

用户选择一个城市并设置降水阈值。

系统根据3 km预测结果和概率集合成员，在地图上突出显示达到阈值的区域。

但这里必须区分两个概念：

**强降水气象风险不等于实际城市内涝风险。**

如果没有接入地表径流、排水能力、地形汇流等资料，就不应直接宣称平台能够预测城市内涝。

**场景二：大风风险辅助研判**

面向区域气象服务、风电和低空行业。

支持：

- 风速阈值设置
- 高风速区域识别
- 风速超阈值概率
- 区域风场空间分析
- 指定位置风速变化分析

这里建议先做好10米风场的展示与分析。

若未来要支持风机轮毂高度风速预测或无人机不同飞行高度的风场分析，需要进一步补充垂直风廓线等模型能力。

因此，第一版应当定位为**近地面大风风险辅助分析**，不直接扩展到完整的低空飞行安全评估。

### ⑦ 模型性能评估（Model Evaluation Lab）

这一模块主要面向科研人员、算法工程师，以及希望了解模型可靠性的专业用户。

它可以充分利用技术文档中已经完成的实验成果。

建议设计四个子功能。

| 子功能 | 具体内容 |
|---|---|
| 模型精度评估 | RMSE、MAE、CRPS |
| 模型对比实验 | Direct Diffusion、U-Net-CorrDiff、当前模型 |
| 地形先验分析 | 有地形与无地形模型的对比 |
| CSC参数分析 | 不同控制系数下的预测性能对比 |

其中，我特别建议突出**CSC跨尺度一致性控制**。

这是你们模型的核心创新之一。

可以在专业分析页面提供参数控制面板：

- CSC低频抑制系数λ
- 残差贡献系数α
- 集合离散度相关参数γ（以实际推理接口支持情况为准）
- 集合成员数量K

用户可以调整参数并执行新的推理任务，观察不同参数下气象场的变化。

需要注意：参数调整应通过后端重新计算获得结果，不能简单在前端对热力图做视觉变化来模拟真实的模型效果。

此外，技术文档也说明当前主对比实验存在样本规模不一致的问题，尚需进一步完成公平对比。因此，Demo可以展示现有实验指标，但应注明实验设置，不能直接将其包装为全面验证过的业务精度保证。

### ⑧ 气象产品与数据服务（Data Products & Services）

一个专业气象分析平台，不应该让用户只能在网页上查看结果。

还需要让用户能够进一步使用这些气象数据。

建议包含三个方面。

**A. 气象产品导出**

用户可以下载：

- 气温分布图
- 风速分布图
- 降水分布图
- 气压分布图
- 集合预测分析图
- 多模型对比图

支持PNG等图片格式。

**B. 气象数据导出**

提供：

- CSV格式的站点或区域统计数据
- NetCDF格式的网格气象数据
- GeoTIFF格式的空间栅格数据

其中GeoTIFF、NetCDF等结构化输出需要后端适配。

**C. 气象分析报告**

用户选择区域、时间和气象要素后，系统自动整理：

- 任务基本信息
- 主要气象要素分析
- 降尺度结果
- 概率集合分析
- 潜在气象风险信息

并形成可导出的分析报告。

后期还可以将相关数据服务封装成API，以便其他行业系统使用。

# 二、如果只做一个Demo，应该优先实现什么？

上面的功能规划是一个相对完整的平台方案。

但是，从实际软件工程的角度出发，我不建议你们在第一版中全部实现。

一方面会增加开发工作量，另一方面也会削弱核心功能的展示效果。

**建议采用“专业气象分析平台”的整体设计，但优先实现一条完整、直观的核心业务流程。**

我推荐第一版 Demo 设计以下六个主要页面。

| 页面名称 | 核心内容 | 为什么需要 |
|---|---|---|
| **Overview** | 综合驾驶舱 | 形成完整平台入口 |
| **Downscaling Studio** | 智能降尺度任务 | 展示模型实际功能 |
| **Weather Explorer** | 高分辨率气象地图 | 展示核心预测结果 |
| **Forecast Comparison** | 预测结果对比 | 直观展示算法价值 |
| **Ensemble Analytics** | 概率集合分析 | 突出生成式模型的优势 |
| **Model Evaluation** | 精度评估与参数分析 | 证明算法效果、展示技术创新 |

此外，可以在后续增加 Risk Intelligence 和 Data Products 页面。

## 推荐的Demo演示流程

假设用户是一名区域气象预报员，需要分析某个山区未来一段时间的近地面大风情况。

可以设计这样一条操作流程：

**第一步：进入综合驾驶舱。**

用户查看当前可用的气象数据，并进入智能降尺度分析。

**第二步：创建降尺度任务。**

选择指定的山区、预报起报时间和预报时效，选择“10米风场”。

**第三步：执行智能降尺度。**

系统调用现有模型，将10 km气象预报重建为3 km气象场。

**第四步：查看高分辨率风场。**

系统跳转到气象地图页面，显示降尺度后的风速热力图及风向矢量。

**第五步：查看降尺度前后的差异。**

用户打开对比分析页面，观察原始ECMWF风场与3 km风场在山脊、山谷等区域的空间差异。

**第六步：分析风速预测不确定性。**

用户查看不同集合成员，以及重点区域的风速概率分布。

**第七步：导出分析结果。**

用户将相关地图与预测数据导出，用于后续业务分析。

这样一条完整的演示流程，能够让用户理解：

**平台不是一个简单的AI算法可视化工具，而是能够实际执行精细化气象分析任务的软件产品。**

对于第一版Demo，建议同时提供预置的历史案例和真实模型推理入口。即使某些实时数据接入能力尚未完成，也可以通过已完成验证的历史样例展示平台工作流程，但必须明确标注数据的实际时间与来源。

MeteoWeave

AI Weather Downscaling & Intelligence Platform
