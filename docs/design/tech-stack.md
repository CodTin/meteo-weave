## 核心框架与语言

### 基础框架
- **框架**: TanStack Start
  - **理由**: 现代化React框架，提供SSR支持，与TanStack生态系统完美集成
  - **替代方案**: Next.js（更成熟但更重），Remix（不同的路由模式）

### 编程语言
- **语言**: TypeScript
  - **配置**: Strict mode (`"strict": true`)
  - **额外配置**: `"noUncheckedIndexedAccess": true` 用于更安全的数组访问
  - **路径别名**: `@/components`, `@/lib` 等
  - **理由**: 严格类型检查可提前捕获错误，对复杂的地理空间数据结构尤为重要

### 运行时与包管理
- **运行时/包管理器**: Bun
  - **理由**: 极快的包安装速度，内置测试运行器、打包器，原生TypeScript支持
  - **考虑**: 某些npm包可能存在兼容性问题，需要准备调试

### 样式方案
- **CSS框架**: Tailwind CSS v4
  - **理由**: 现代化、性能优化、与组件库配合良好
- **CSS变量**: 用于主题化和动态颜色方案
  - **用例**: 温度梯度（蓝→红）、降水量（浅→深）、可定制的图表主题
  - **理由**: 与Shadcn UI的CSS变量方法集成，支持动态主题切换

### 组件库
- **基础组件**: Shadcn UI（二次开发）
  - **理由**: 无依赖、完全可定制、优秀的设计系统、与Tailwind CSS紧密集成
  - **包含**: 表单组件、骨架屏、Toast通知、图表组件等

## 数据层

### 数据获取与缓存
- **数据获取**: TanStack Query (React Query)
  - **功能**:
    - 自动请求去重
    - 后台重新获取陈旧数据
    - 乐观更新
    - 内置加载/错误状态
    - 与TanStack Start的SSR能力集成
  - **理由**: 处理大型NetCDF/Zarr数据集和时间序列数据的理想选择

### API层架构
- **API客户端**: TanStack Start Server Functions（作为代理层）
  - **职责**:
    - API密钥管理（保持服务器端密钥安全）
    - 响应转换
    - 错误处理
    - 速率限制
  - **数据流**: 外部API → Server Functions → TanStack Query → React组件
  - **理由**: 保持API密钥安全，提供从服务器到客户端的类型安全，集中数据访问逻辑
  - **替代方案**: oRPC（对于简单的代理场景过于复杂，适合微服务架构）

### 状态管理
- **客户端状态**: Zustand
  - **用例**: UI状态（选中区域、活动图层、对比模式、过滤器）
  - **理由**: 轻量级、样板代码少、与React 18+配合良好、比Redux简单但比Context更结构化
  - **状态模式**: 存储模型（store-based），适合地图设置和UI偏好
  - **替代方案**: Jotai（原子化，适合高度响应式UI）

### 表单管理与验证
- **表单库**: React Hook Form
  - **特性**: 最小重渲染、性能优化
- **验证**: Zod
  - **特性**: 类型安全的验证模式、服务器端验证支持
- **集成**: 与Shadcn UI表单组件深度集成
- **理由**: 当前现代标准，提供优秀的TypeScript支持，Shadcn UI的表单组件专为RHF + Zod构建
- **替代方案**: TanStack Form（生态系统一致性好，但Shadcn UI集成需要额外工作）

### 环境变量
- **配置管理**: t3-env
  - **功能**:
    - 运行时环境变量验证
    - 类型安全访问
    - 缺失/无效配置的清晰错误消息
    - 基于Zod的模式（与验证方法一致）
  - **理由**: 提供一致的验证模式，防止配置错误导致的运行时错误

## 可视化与地图

### 地理空间可视化
- **地图库**: Mapbox GL JS
  - **功能**:
    - WebGL渲染以获得性能
    - 优秀的瓦片图层支持
    - 交互式控件
  - **React集成**: react-map-gl
  - **理由**: 现代、高性能、为气象数据可视化需求提供正确的功能平衡
  - **替代方案**: MapLibre GL JS（开源版本），Leaflet（较旧但更简单），deck.gl（数据可视化层很棒）

### 地理空间计算
- **计算库**: Turf.js
  - **功能**:
    - 点在多边形内检查
    - 距离计算
    - 边界框操作
    - 坐标转换
    - GeoJSON工具
  - **理由**: 浏览器端地理空间操作的标准库，轻量级，处理坐标/区域选择功能必不可少
  - **协同**: 补充Mapbox（处理渲染）与计算几何

### 类型定义
- **地理空间类型**: @types/geojson
  - **提供**: Feature, FeatureCollection, Point, LineString, Polygon, Geometry类型，坐标数组
  - **理由**: 处理地理空间数据结构时的类型安全至关重要，防止坐标顺序错误和几何不匹配

### 图表可视化
- **图表库**: Shadcn UI Charts（基于Recharts）
  - **功能**:
    - 预设样式匹配Shadcn UI主题
    - 开箱即用的可访问组件
    - 减少自定义样式工作
  - **用例**: 温度曲线、降水模式、多轴图表
  - **理由**: 声明式API匹配React模式，活跃维护，提供气象可视化所需组件
  - **底层**: Recharts（React原生、声明式、基于D3原语）

### 数据表格
- **表格组件**: TanStack Table
  - **功能**:
    - Headless UI（使用Tailwind + Shadcn样式化）
    - 排序、过滤、分页
    - 列调整大小、固定
    - 大数据集虚拟滚动
    - TypeScript优先
  - **用例**: 显示表格气象数据（预报、历史记录、对比表）
  - **理由**: TanStack生态系统的另一部分，headless设计适合Shadcn UI样式，处理气象数据集的复杂显示需求

## UI与交互

### 图标库
- **图标**: Lucide React
  - **特性**: 现代、可树摇、一致的设计风格、1000+图标
  - **理由**: Shadcn UI的默认选择，提供优秀的覆盖范围，与组件库保持视觉一致性
  - **替代方案**: Heroicons（也兼容），Radix Icons（Shadcn UI的替代选择）

### 日期/时间处理
- **日期库**: date-fns
  - **特性**: 现代、可树摇、不可变、优秀的TypeScript支持
  - **用例**: 预报、历史数据、时间范围的时间数据
  - **理由**: 现代标准，树摇以获得更小的包体积，处理所有气象时间序列需求，无旧库的臃肿
  - **替代方案**: Day.js（更小但功能较少），Luxon（更重，功能更多）

### 文件处理
- **文件上传**: react-dropzone + 原生File API
  - **react-dropzone功能**:
    - 拖放 + 点击上传
    - 文件验证（大小、类型）
    - 易于使用Tailwind样式化
    - 轻量级（~10KB）
  - **下载**: 原生下载链接
  - **理由**: react-dropzone专注、成熟、与原生File API干净集成，比Uppy等全功能解决方案更简单

### 加载状态
- **骨架屏**: Shadcn UI Skeleton
  - **功能**: 一致的加载状态、防止布局偏移、比加载器更好的用户体验
  - **理由**: 已在组件库中，为数据密集型气象显示提供精致的加载状态

### 通知系统
- **Toast通知**: Shadcn UI Toast (Sonner)
  - **功能**: 美观的动画、可访问、现代
  - **用例**: 用户反馈（API调用失败、数据加载、操作完成）
  - **理由**: 现代toast库，与Shadcn UI集成，用户反馈必不可少

## 认证与数据库

### 认证方案
- **当前**: Mock认证（硬编码账号用于演示）
  - **实现**: 自建登录页面，预设几个不同身份的账号
  - **理由**: 这是一个Demo平台，无需完整的用户登录/认证系统
- **未来（如需要）**: better-auth
  - **理由**: 现代、灵活、优秀的TypeScript支持

### 数据库
- **数据库**: Vercel Postgres（仅在需要持久化时）
  - **由**: Neon提供支持
  - **功能**:
    - Serverless PostgreSQL
    - 内置连接池
    - 与Vercel集成
    - 慷慨的免费层
  - **用例**: 如果需要保存用户场景、配置、收藏
  - **决策**: 如果用户只与实时数据交互而不保存，则跳过数据库
  - **替代方案**: Supabase（Postgres + 实时 + 存储），Turso（边缘SQLite）

### ORM
- **ORM**: Drizzle ORM（如果使用数据库）
  - **优势**:
    - TypeScript优先
    - 轻量级（与Prisma相比）
    - 类SQL语法
    - 优秀的类型推断
    - 与Vercel Postgres配合良好
    - 边缘函数性能优于Prisma
  - **理由**: 现代、轻量级，非常适合TanStack Start的server functions

## 测试与质量

### 单元测试
- **测试框架**: Vitest
  - **功能**:
    - Vite原生（快速，与构建设置配合）
    - Jest兼容API
    - 内置TypeScript支持
    - 使用@testing-library/react进行组件测试
    - 快速监视模式
  - **理由**: 现代、快速、为基于Vite的项目设计，TanStack Start与Vite配合使用

### E2E测试
- **E2E框架**: Playwright
  - **功能**:
    - 跨浏览器测试
    - 内置测试运行器
    - 网络拦截（模拟API响应）
    - 截图和追踪
    - 优秀的调试工具
  - **理由**: 现代、全面、当前E2E测试标准，对于测试复杂地图交互和数据可视化流程至关重要
  - **替代方案**: Cypress（较旧的范式）

### 可访问性测试
- **a11y测试**: @axe-core/playwright
  - **功能**:
    - WCAG合规性检查
    - 屏幕阅读器兼容性
    - 键盘导航
    - 颜色对比验证
  - **理由**: 自动化可访问性测试可提前发现问题，对于面向公众的演示平台很重要

### 代码质量工具
- **Linting**: oxlint
  - **特性**: 比ESLint快50-100倍（基于Rust）
  - **考虑**: 截至2024年底仍在成熟中，可能需要ESLint补充某些规则
  - **策略**: 以oxlint开始，如需要则回退到ESLint
  - **理由**: 符合"现代、不过时"的要求
  
- **Formatting**: oxfmt
  - **特性**: 比Prettier快，更有主见（配置选项更少）
  - **理由**: 现代、快速、与oxlint配合良好

- **Pre-commit Hooks**: lint-staged + husky
  - **功能**: 提交前确保一致的代码风格并捕获错误
  - **理由**: 行业标准，最小开销，防止风格争论并提前捕获错误

## 构建与部署

### 部署平台
- **平台**: Vercel
  - **功能**:
    - 为React框架优化
    - Serverless函数
    - 自动部署
    - 边缘网络
    - 内置优化
  - **理由**: 与TanStack Start配合良好，提供优秀的开发者体验

### 渲染策略
- **渲染**: SSR with client-side hydration
  - **方法**:
    - 服务器端渲染初始UI/chrome
    - 客户端水合地图组件（Mapbox需要浏览器API）
  - **优势**:
    - SEO（如果面向公众）
    - 初始加载性能
    - 服务器端数据获取
  - **理由**: 平衡性能和复杂性

### 图像优化
- **优化**: Vercel内置图像优化
  - **功能**: 自动格式转换（WebP/AVIF）、大小调整、优化文件大小
  - **理由**: 比自己管理sharp更简单，Vercel自动处理

### 包分析
- **分析**: 是，定期检查
  - **工具**: Bundle analyzer（TanStack Start等效）
  - **用途**: 识别大型依赖项、优化导入、跟踪包增长
  - **理由**: 鉴于地图库和图表依赖项，保持包大小受控很重要

## 监控与分析

### 错误追踪
- **错误监控**: Sentry
  - **功能**:
    - 实时错误警报
    - 堆栈跟踪
    - 用户会话重放
    - 性能监控
    - 与Vercel集成
  - **理由**: 免费层慷慨，与Vercel无缝集成，提供生产错误可见性，对于用户交互的演示平台至关重要

### 分析
- **分析**: Vercel Analytics
  - **功能**: 页面浏览、核心Web指标、基本用户见解
  - **理由**: 零配置（Vercel部署时内置），隐私友好，提供基本见解而无复杂性
  - **替代方案**: Plausible/Umami（隐私为中心），Google Analytics（全面但隐私问题）

### 实时更新
- **策略**: TanStack Query重新获取间隔（轮询）
  - **配置**: 每1-5分钟轮询一次
  - **理由**: 对于气象数据（每几分钟更新一次）足够，比WebSockets/SSE更简单，天气数据不需要亚秒级更新
  - **替代方案**: Server-Sent Events（SSE），WebSockets（双向，更复杂）

## 开发工作流

### 项目结构
- **结构**: 单包（非monorepo）
  - **理由**: 这是一个演示平台，保持简单，如果需要可以稍后重构为monorepo

### 文档
- **API文档**: 无
  - **理由**: 这是面向最终用户的演示平台，不是开发者API，TypeScript类型为内部开发自我记录
  
- **组件文档**: 无Storybook
  - **理由**: 对于演示平台来说是开销，在上下文中开发组件，如果组件库显著增长可以考虑

### PWA支持
- **PWA**: 否
  - **理由**: 气象平台需要实时数据和活跃的互联网连接，离线模式对实时天气预报没有意义

### 国际化
- **i18n**: 否
  - **当前**: 单语言
  - **理由**: 目前不考虑多语言支持，如果需要可以稍后添加
  - **未来（如需要）**: next-intl（与TanStack Start配合，类型安全翻译）

## 关键架构模式

### 1. 服务器-客户端边界
```
外部API → TanStack Start Server Functions → TanStack Query → React组件
```
- Server Functions充当安全的API代理层
- 保持API密钥服务器端
- 提供从服务器到客户端的类型安全

### 2. 状态架构
```
服务器状态（TanStack Query）+ 客户端UI状态（Zustand）
```
- **服务器状态**: 从API获取的数据、缓存、重新验证
- **客户端状态**: UI偏好、地图交互、选中的区域、活动图层

### 3. 样式策略
```
Tailwind工具类 + CSS变量（主题化）+ Shadcn UI组件
```
- Tailwind用于快速UI开发
- CSS变量用于动态主题（温度梯度、图表颜色）
- Shadcn UI提供一致的组件系统

### 4. 表单模式
```
React Hook Form + Zod模式 + Shadcn表单组件
```
- React Hook Form处理表单状态
- Zod提供运行时验证和TypeScript类型
- Shadcn UI提供可访问的表单组件

### 5. 地图架构
```
Mapbox GL JS（渲染）+ Turf.js（计算）+ Zustand（地图状态）
```
- Mapbox处理地图渲染和交互
- Turf.js进行地理空间计算
- Zustand管理地图状态（图层、选择、缩放）
